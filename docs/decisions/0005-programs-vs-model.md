# ADR-0005：节目事实由程序决定，模型只负责表达

日期：2026-10-31
状态：已采纳

## 背景

设计文档要求：harness 是互动脑，节目维护确定性的玩法状态；
“模型不能越过程序规则直接改分数、决定工具权限或终止别人的任务”。
同时又要求“不要先交付一个只会锐评的固定流水线”。

两者看似矛盾，实际是两个不同的问题：

- 不能让**模型**决定分数/权限/结算；
- 也不能让**系统**只会一种固定节目。

## 决策

1. 引入 `ProgramManager` + 命令解析：确定性节目（LOL / 签名 / Boss）由程序处理，
   普通文本仍走模型聊天。
2. 命令解析只做**完全匹配**（`攻击`、`签名 xxx`），不匹配就落回 chat，
   避免“治疗一下我的菜”被劫持成游戏动作。
3. 节目产出事实（战绩、签名文件、结算结果）与台词；
   台词由节目直接给（确定性），或交给模型润色（`usesModel` 标记）。
4. **两个工具执行器**：模型执行器只有只读白名单；节目执行器额外有 `signature.create`。
   模型拿不到写权限是结构保证，不是配置约定。
5. Boss 的“每观众一次”由内存 Map + 数据库唯一约束双重保证；
   迟到输入、重复提交、重复结算都有测试。

## 影响

- 优点：玩法可预测、可测试、可复现；模型故障不影响节目结算。
- 代价：节目台词不如模型灵活；需要为每个节目写确定性的文案与规则。
- 边界：LOL 的数据是 mock；签名不是真人手写；Boss 数值是首版调参值，不是平衡性结论。
- 后续：`docs/tasks.md` 的 REAL-* 项是把 mock 换成真实服务，不改这套结构。

## 替代方案

- 全交给模型：分数会被幻觉污染，且无法做“每观众一次”的强约束。
- 全写成固定命令：会退化成设计文档明确禁止的“只会锐评的固定流水线”。

## 补充（同日，审查后修正）

只读审查发现了 3 个真实缺陷，已修复并有测试守护：

1. **窗口到期没有结算路径**：原本只有「下一个观众提交」会惰性结算，
   没人再发弹幕时回合永远停在 `open`，DB 也停在 `open`。
   现在：`BossProgram.onSettled` 作为唯一结算出口 + runtime 里 1s 的 `programs.tick()`。
2. **先写库后校验**：被拒绝的动作（窗口已关、重复）会写进 `game_actions`，
   污染统计。现在：先 `boss.submit()` 校验，再落库；落库失败调用 `revertSubmission` 回滚内存。
3. **命令劫持闲聊**：裸动作词（`打`、`奶`、`治疗`）在任何节目都生效，
   观众闲聊会被回一句“发「开Boss」开始”。
   现在：只有显式前缀（`/` `#`）或当前就在对应节目时才认；`开Boss` 作为节目入口随时可用；
   去掉容易误伤的裸 `查`；`签名怎么弄啊` 不再生成签名。

另外顺手修了：媒体 `cache-control` 与全局 `no-store` 冲突、ingest 同步等待慢节目（改为异步）、
取消不覆盖正在合成的语音、句级时间片末句不覆盖整段、公开纪念品写入观众昵称。
